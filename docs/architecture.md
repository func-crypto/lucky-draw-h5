# LuckyDraw H5 V1 技术设计

## 目标

V1 优先保证现场抽奖的正确性：一人一次、必中奖、库存不超发、重复进入可恢复原结果。

## 关键一致性策略

抽奖接口由服务端决定结果。事务开始后先对活动行执行 `SELECT ... FOR UPDATE`，将同一活动的抽奖临界区串行化，再检查用户是否已有中奖记录，随后读取仍有库存的奖品、按剩余库存权重随机选取、扣减库存并写入中奖记录。

V1 单场仅 260 份奖品，串行临界区换取最简单可靠的一致性是合适的。后续若活动规模上升，可替换为 Redis/Lua 或数据库细粒度锁方案，不改变 API 契约。

数据库同时建立 `(activity_id, openid)` 唯一约束，作为“一人一次”的最终防线。

## 身份边界

当前 `X-User-OpenId` 仅用于开发联调。正式环境禁止信任前端传入 OpenID，必须通过微信 OAuth 回调建立服务端会话，再由会话解析当前用户身份。

## 抽奖概率

当前采用剩余库存权重随机。例如剩余库存为 20/50/80/110，则总票数为 260，每件实物对应一张票。抽中后该奖品库存减 1，因此库存为 0 的奖品自然不再被抽中。

这保证所有奖品在 260 次有效抽奖后恰好发完，同时不会出现空奖。
