# Architecture

## 目标

LuckyDraw H5 是一次线下抽奖活动，不按大型营销平台建设。V1 优先保证：代码少、依赖少、部署简单、库存不超发、同一用户不能重复抽奖。

## 架构

```text
微信 / 浏览器
    │
    ├── H5 静态页面（Vue 3）
    │
    └── /api
          │
       Node.js
          │
       SQLite
```

生产环境构建 H5 后，Node 服务可以直接托管 `h5/dist`，因此一台小服务器只需要运行一个 Node 进程和一个 SQLite 数据文件。

## 数据表

仅保留三张核心表：

- `activities`：活动；
- `prizes`：奖品及库存；
- `draws`：用户中奖记录。

`draws(activity_id, openid)` 使用唯一约束，保证同一用户在同一活动中只有一条中奖记录。

## 库存安全

抽奖使用 SQLite `BEGIN IMMEDIATE` 写事务：

1. 再次检查用户是否已抽；
2. 读取仍有库存的奖品；
3. 按剩余库存做权重随机；
4. 对中奖奖品执行 `remaining_stock - 1`；
5. 写入中奖记录；
6. 提交事务。

这样无需 Redis 或单独的锁服务，也能满足本项目现场规模的并发需求。

## 微信身份

当前开发阶段使用 `X-User-OpenId` 模拟身份。正式微信 OAuth 接入后，只需要把身份来源改为服务端可信的微信会话，数据库及抽奖流程保持不变。
